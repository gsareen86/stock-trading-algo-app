# Swing & Long-Term — an equity research platform for Indian markets

A **paper-trading research platform**. It reads NSE-listed stocks against four independent
strategies and tells you what each one thinks — in plain English, with every number traceable
back to the measurement that produced it.

It does not place orders. It does not manage your money. It is a tool for deciding, and the
deciding stays with you.

> **New to investing?** Start with [What this actually does](#what-this-actually-does) below.
> You do not need to know what a moving average is to use it — but you should read
> [Before you rely on any of this](#before-you-rely-on-any-of-this).

## Running it

You need **Python 3.11+** and **Node 20+**.

```powershell
# 1. Backend dependencies (once)
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[llm,agents,dev]"
.\.venv\Scripts\python.exe -m alembic upgrade head

# 2. Create your login (once)
$env:AUTH_BOOTSTRAP_PASSWORD = "choose-a-long-password"
.\.venv\Scripts\python.exe -m app.auth.cli create-user yourname

# 3. Frontend dependencies (once)
cd ..\web
npm install

# 4. Start everything
cd ..
.\run-local.ps1
```

Then open **http://localhost:3000** and sign in.

`run-local.ps1` starts the API on port 8000 and the web app on port 3000. Set
`AUTH_SECRET_KEY` to a long random string before running this anywhere other than your own
machine — see [Configuration](#configuration).

## What this actually does

Every day (when you ask it to), it:

1. **Screens** the NSE 500 down to stocks that are actually tradable — enough history, enough
   daily turnover, not under an exchange surveillance measure.
2. **Runs four strategies** over each one. They are independent and they often disagree.
3. **Explains** each verdict in plain English, with every figure checked against the underlying
   measurement.
4. **Watches what you hold** and tells you when something changes — most importantly, when the
   strategy that justified a holding no longer likes it.

### The four strategies

Each answers a different question. None of them is "the" answer.

| Strategy | Looks for | In plain terms |
|---|---|---|
| **Minervini** | Confirmed uptrend, then a tightening base | A stock already going up that has paused to catch its breath |
| **Brahma-Vishnu-Mahesh** | Market → sector → stock, in that order | A good stock, in a strong sector, in a rising market |
| **Fundamental-Technical Momentum** | Earnings growth first, chart second | A business genuinely improving, before the market notices |
| **Young Momentum** | Breakout, push, pause, continue | A move that has already proven itself and is resuming |

### Why there is no single score

The obvious thing to build is one number — "this stock scores 78" — and this platform
deliberately does not.

A previous version did exactly that, and it hid the thing that mattered: a stock could score
well overall while failing a check that should have ruled it out entirely. Averaging four
opinions produces a number that is not any of them.

So you see four verdicts side by side. **When they disagree, that is information**, not a
gap in the tool — it usually means the stock looks good by one measure and not by another, and
that is worth knowing before you commit money.

> **How to read disagreement, as a beginner:** broad agreement is rare and worth paying
> attention to. One BUY among three AVOIDs usually means one strategy has found something
> specific rather than that the stock is broadly attractive. There is no rule that says
> "three out of four means buy" — if there were, this tool would compute it for you.

## Before you rely on any of this

Read this part.

- **Paper trading only.** No orders are placed anywhere. Nothing here touches a real broker
  account.
- **Profit and loss figures are gross.** Brokerage, STT, stamp duty and GST are *not*
  modelled. Real returns are lower — materially so at swing-trading frequency.
- **Backtests flatter every strategy.** The historical replay uses today's index members, so
  companies that were delisted or removed are invisible to it. It also models no slippage.
  Every backtest result says this on it; read that part.
- **The explanations are generated by a language model**, and are checked so that every number
  in them comes from a real measurement. A narrative that fails that check is discarded rather
  than shown — so a missing explanation means "we would not stand behind it", not "nothing
  happened".
- **This is not financial advice**, and nothing here knows your circumstances, tax position or
  risk tolerance.

## The six screens

| Screen | Answers |
|---|---|
| **Today** | What needs my attention right now |
| **Ideas** | What could I buy — every strategy's verdict, side by side |
| **Positions** | What do I own, and is the shape of my portfolio sensible |
| **Stock** | Everything known about one company |
| **Performance** | How am I doing, and what has each strategy actually done |
| **Engine** | Under the hood — model cost, failures, what ran |

## Configuration

Settings are environment variables. Nothing is read from the database at runtime.

| Variable | What it does |
|---|---|
| `AUTH_SECRET_KEY` | **Required outside dev.** Signs your login tokens; must be 32+ characters. Generate: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `DATABASE_URL` | Defaults to a local SQLite file. Point at Postgres for anything shared. |
| `LLM_ROUTE__NARRATIVE` | Which model writes explanations, e.g. `ollama/gemma4:12b` for a local one |
| `LLM_LOCAL_TIMEOUT_SECONDS` | Defaults to 300. Local models are slow; the hosted default of 30 is far too short for them. |
| `LLM_DAILY_BUDGET_INR` | Daily spend cap in rupees for paid models. Local models are free and never blocked by it. |
| `MCP_SERVER__KITE` | Zerodha Kite MCP, for looking up live quotes and holdings |

Explanations work with a **local model** (Ollama, LM Studio) at no cost, or a hosted one if you
prefer. With no model configured at all, everything still works — you get the numbers without
the prose.

## Layout

```
backend/     FastAPI, the strategies, the ledger, the agent graph
web/         Next.js — the six screens
openspec/    The living specification: what everything does and why
run-local.ps1
```

`openspec/project.md` is the map. Every behaviour has a written specification in
`openspec/specs/`, and every change that produced one is archived in `openspec/archive/` with
the reasoning that led to it.
